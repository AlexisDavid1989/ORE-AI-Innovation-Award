How to Enter

Six steps from idea to submission. Fill in the form, grab the kit, build the project, complete SUBMISSION.md, upload the project, and add your video.

Fill in the form

Fill in the online form and let us know you're in the game. Tell us what you're going to build, who's with you, the name of the project, and the data used. We will then provide you access to the GitLab repository.

Grab the submission kit

Clone the project GitLab repository and create your own branch. It includes the standard submission form and the automatic Copilot usage tracking. You can also grab the submission kit from the Documents / Submission Kit folder.

Build your project

Make something AI-centered and relevant to ORE. Everyone uses GitHub Copilot for this award, and usage is captured automatically, so there's nothing to track by hand.

Fill in SUBMISSION.md

Complete the standard form: the problem, your approach, technologies and models used, setup instructions, the value it delivers, and who's behind it. Every field earns its place.

Upload your project

Push your project to its own branch in the GitLab repository, and don't forget to add the auto-generated Copilot files — untouched: COPILOT_USAGE_REPORT.md, usage-summary.json, and prompt-answer-log.jsonl.

Upload your video

Upload your demonstration video to the award SharePoint page in Documents / Submissions / Videos. This is necessary if you want people to vote for your project.

A practical definition

What is a token?

A token is the unit of text an AI model counts when it reads input or generates output. It is not the same as a word, character, or line of code.

How text becomes tokens

A tokenizer breaks text into pieces the model can process. A token may be a whole word, part of a word, punctuation, whitespace, a number, or a code symbol. Common words are often compact; uncommon words, long identifiers, and mixed languages usually need more pieces. The exact split depends on the model.

TextSplit into tokensWhy
"Please summarize this file"Please · summarize · this · file = 4 tokensCommon whole words are usually a single token each.
"internationalization"international · ization = 2 tokensLong, uncommon words are split into smaller pieces.
"2026-08-27"2026 · - · 08 · - · 27 = 5 tokensNumbers and punctuation are usually counted separately.
"for (i = 0; i < 10; i++)"words, punctuation, and symbols = several tokensCode syntax rarely maps cleanly to whole words.

These are simplified illustrations, not Copilot's exact tokenizer. One word is not always one token, and one token is not always one word.

Curious how your own text splits into tokens? Try OpenAI's interactive Tokenizer tool and paste in a sentence or a snippet of code to see it broken down live.

Once text is tokenized, each token is read by the model as part of its input sequence. When generating a reply, the model predicts and outputs one token at a time, adding each new token to the growing answer until the response is complete. Those output tokens are then converted back into readable text and returned to you as completion tokens.

A rough scale

OpenAI publishes a rough estimate for English text with its own tokenizer: about 4 characters per token, or roughly 750 words per 1,000 tokens. This is an approximation, not a fixed rule: it varies by model and tokenizer, and Copilot's underlying models may not split text the same way. Code, non-English languages, and unusual identifiers typically need more tokens per word than plain English prose. Every model also has a maximum context window, a limit on how many tokens it can hold in a single request, which is why very long conversations or large files can eventually need to be trimmed or summarized.

Source: OpenAI, "Understanding and counting tokens".

What it does — and never does

✅ Runs 100% locally

A plain PowerShell script on your machine. No network calls, no upload — nothing leaves your computer.

✅ Costs zero tokens

It reads log files that already exist and never calls an AI model. Free of charge.

✅ This workspace only

It matches your project folder and summarizes that project's Copilot sessions.

🚫 Never reads your text

The wording of your prompts and Copilot's answers is never opened, stored, or sent anywhere.

🚫 No conversation content

Only token counts and structured metadata (model, mode, tools) are kept — no messages.

✅ Fully inspectable

The script is a short, readable file in your project. Open it and see for yourself.

Two separate views: the first donut shows where tokens came from; the second shows what type of work requests used tools for. They are calculated independently and are not expected to reconcile.

Follow the tokens

Where your Copilot tokens go

Every request spends tokens on a few different things. This split shows where the tokens came from: messages, tool results, files, system instructions, and Copilot's answer.

100%of tokens
  • Your prompts & chat historyWhat you typed, plus earlier turns resent each request 51%
  • Data read into contextTool, terminal, and search results pulled in to answer 24%
  • System overheadCopilot's own base instructions 22%
  • Files read into contextSource files you added to the chat 1%
  • Answer generated by CopilotTokens written back to you — an exact count 2%

Illustrative example. Your real split comes straight from Copilot's own per-request token breakdown — the script maps those numbers and never reads the underlying text.

How the token sources are calculated

For prompt sources, the script applies each JSON percentage to promptTokens. Answer tokens come directly from completionTokens.

Sub-agent token notice: totals include only model requests present in the local VS Code logs. A sub-agent invocation may be visible without its child model calls being recorded, so sub-agent token usage may not be included in the reported total.

JSON fieldsBrief explanationReport name
User Context / MessagesYour prompt and earlier conversation messagesuser_prompt_tokens
User Context / Tool ResultsSearch, terminal, or other tool output included in contextreading_data_tokens
User Context / FilesFiles included as project contextreading_code_structure_tokens
SystemSystem instructions and operating rulessystem_overhead_tokens
completionTokensTokens in Copilot's generated answeranswer_generation_tokens

Example JSON:

{
  "promptTokens": 10000,
  "completionTokens": 500,
  "promptTokenDetails": [
    { "category": "User Context", "label": "Messages", "percentageOfPrompt": 20 },
    { "category": "User Context", "label": "Tool Results", "percentageOfPrompt": 30 },
    { "category": "User Context", "label": "Files", "percentageOfPrompt": 10 },
    { "category": "System", "percentageOfPrompt": 40 }
  ]
}

Explanation: the request contains 10,000 prompt tokens. The percentages divide them into 2,000 message tokens (classified as user_prompt_tokens), 3,000 tool-result tokens (classified as reading_data_tokens), 1,000 file-context tokens (classified as reading_code_structure_tokens), and 4,000 system-overhead tokens (classified as system_overhead_tokens). The response contains 500 completion tokens, recorded as answer_generation_tokens.

What the work looked like

How activity is categorized

Requests are sorted into a handful of activity types so the mix of building, reading, and debugging is visible at a glance. This is a separate view from the token-source donut above.

100%of activity
  • Refactor & editingEdit and patch tools60%
  • Reading code structureSearch, read, and list tools11%
  • Code generationFile-creation tools8%
  • Debugging & testingTerminal, error, and test tools4%
  • Planning & docsPlan mode3%
  • UnclassifiedNo recognized tool or mode signal14%

Categories are inferred from which tools ran and which mode you used — not from the words in your prompt. Token counts are exact; the category labels are best-effort and marked as inferred.

How the categories are calculated

Each request gets one category from its tool IDs. That category receives the request's full promptTokens + completionTokens.

Tool IDBrief explanationClassification

run_in_terminalRuns a terminal commanddebugging_testing

findfilesSearches for files by name or patterncode_structure_reading
findtextinfilesSearches for text across filescode_structure_reading

Example JSON:

{
  "promptTokens": 2000,
  "completionTokens": 100,
  "response": [
    { "kind": "toolInvocationSerialized", "toolId": "applypatch" },
    { "kind": "toolInvocationSerialized", "toolId": "run_in_terminal" }
  ]
}

Explanation: the request uses applypatch, so it is classified as refactor_editing. That category receives 2,100 tokens (2,000 prompt tokens + 100 completion tokens). Although run_in_terminal also appears, editing has higher priority and the request is counted only once.

In short: the tracking is a local, zero-cost tally of how many tokens went where and which tools you reached for. It can't see, keep, or share what you and Copilot actually said. Please just leave the generated files untouched — their integrity is part of judging.
